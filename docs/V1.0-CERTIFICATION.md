## 3. Segurança

- Senhas: hash bcrypt. A senha original nunca é devolvida.
- JWT HS256, validade 12h. Produção exige `JWT_SECRET` forte (mín. 16, fora da lista de valores fracos).
- Revogação: `POST /api/auth/logout` com `{ revoke: true }` incrementa `token_version`. Token revogado recebe 401.
- Cookie HttpOnly permanece opcional (`CDS_AUTH_COOKIE`).
- Tentativa de revelar senha do cliente: `403 PASSWORD_NOT_RECOVERABLE` e auditoria `SENSITIVE_DATA_ACCESSED`.
- Documentos: AES-256-GCM (`CDSE1`), chave `DOCUMENT_ENCRYPTION_KEY` (mín. 32 em produção). Decrypt só em memória para view/download.
- Acesso a documento: `tenant_id` + `company_id` + permissão. Tenant ou empresa diferentes: 404.
- STAFF não administra credencial/perfil `CLIENT_ADMIN`.
- Produção: `DEMO_MODE=true` impede a subida. Ausência/chave inválida gera erro claro, sem stack de segredo nos logs da suíte de boot.

## 4. Armazenamento de documentos

- Persistência em `documents` com `storage_path` relativo: `documents/{id}/arquivo`.
- Caminho físico = `path.join(UPLOAD_DIR, storage_path)` via `DocumentStorageService`.
- O banco não guarda `C:\projetos\…`, `D:\…` nem `/home/usuario/…`.
- Upload PDF e imagem cobertos. Arquivo em disco começa pelo magic `CDSE1`.
- View autorizada devolve o conteúdo original (ex.: `%PDF-`). Download usa `Content-Disposition: attachment`.
- Auditoria `DOCUMENT_VIEWED` / `DOCUMENT_DOWNLOADED`.
- Exclusão lógica (`deleted_at`); view após exclusão: 404.
- Migração: `npm run migrate:documents`. Órfãos em `logs/ORPHAN_DOCUMENTS.json` (não apagados automaticamente).

## 5. Autenticação e credenciais

Fluxo certificado: convite → definição de senha → hash → login → logout → logout com revoke.

Portal do escritório exibe **CONFIGURADA** ou **NÃO CONFIGURADA**. Nunca a senha original.

Perfis de cliente:

| Perfil | Visualizar | Operar lançamentos/despesas | Administrar usuários/credenciais admin |
|---|---|---|---|
| `CLIENT_ADMIN` | sim | sim (portal) | sim, conforme regra |
| `CLIENT_FINANCE` | sim | sim (portal) | não (sem permissões `client.users.*`) |
| `CLIENT_VIEWER` | sim | não (403 em criação) | não |

Escritório: `OWNER` / `ACCOUNTANT` / `STAFF`. STAFF respeita isolamento e não cria/gerencia `CLIENT_ADMIN`.

## 7. Contábil

Além de débito = crédito:

- conta ativa, analítica/postável, do tenant correto
- conta sintética, inativa ou de outro tenant: bloqueada
- semântica (`validateAccountingSemantics`): despesa, receita e manual não aceitam o mesmo par D/C na mesma conta
- exceções válidas: `TRANSFER`, `RECLASSIFICATION`, `ADJUSTMENT`, `OPENING`

O fluxo Cliente → despesa → documento → classificação → lançamento → aprovação → `POSTED` → exportação permanece coberto pela suíte (sprints 7, 13, 14 e 15).

## 8. Backup e restore

```
npm run backup
```

Gera `backups/backup-<timestamp>/` com banco (+ WAL/SHM se existirem), `uploads/` e `MANIFEST.json`. Não inclui `.env`.

Restore:

```
node scripts/restore.js backups/backup-XXXX/cds-contabil-connect.db <destino>
```

Copia o `.db` e a pasta `uploads/` **ao lado do backup**. Sem essa pasta, usa `uploads/` do repositório.

Validação desta certificação (cópia operacional):

- backup `backups/backup-2026-09-19T00-54-58-247Z`
- restore em diretório temporário
- `PRAGMA integrity_check` = `ok`
- `PRAGMA foreign_key_check` = nenhum erro
- 5 documentos relativos presentes no destino
- 0 arquivos ausentes em `uploads/documents/{id}/…`

Para abrir documentos criptografados após restore, `DOCUMENT_ENCRYPTION_KEY` e `JWT_SECRET` devem ser os mesmos do ambiente de origem.

## 9. Configuração de produção e DEMO

Produção (`NODE_ENV=production`) recusa iniciar se:

- `JWT_SECRET` ausente, fraco ou curto
- `DOCUMENT_ENCRYPTION_KEY` ausente, de desenvolvimento ou com menos de 32 caracteres
- `DEMO_MODE=true`

`DEMO_MODE=true` (somente não-produção): seed cria usuários demo; dicas de login só quando `/api/health.demo` permite. Produção não aceita demo.

Referência de variáveis: `.env.example` (placeholders, sem `DB_FILE`, sem chaves reais).

## 14. Limitações conhecidas do V1.0

- Um processo / um arquivo SQLite. Sem cluster nem réplica automática.
- E-mail e WhatsApp são opcionais; sem provider o convite registra `EMAIL_NOT_CONFIGURED`.
- Logout padrão **não** revoga o JWT (compatibilidade com fluxos de troca de senha). Revogação exige `{ revoke: true }`.
- Cookie de sessão não é o modo padrão.
- Restore de documentos criptografados exige a mesma `DOCUMENT_ENCRYPTION_KEY`.
- Frontend é JavaScript estático; cache de assets versionado manualmente.
- A suíte usa `concurrency=1` por causa do SQLite.

Nenhuma dessas limitações é falha aberta da certificação.
